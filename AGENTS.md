## Workspace facts

- **Git — GitHub is primary (`origin`).** Push and CI run on **`origin`** (`github.com/CountableNewt/latr-link`). Vercel deploys branch previews and `main` production; GitHub Actions verifies Go, Bun and native clients. A **`tangled`** remote may exist but is not used for CI/deploy right now — default: `git push origin <branch>`. **`dev`** / **`main`** track **`origin/*`**; repo **`remote.pushDefault=origin`**.
- Monorepo root: Bun workspaces (`apps/*`, `packages/*`, `services/*`) + Turborepo. Pin **Bun 1.3.14** (`package.json` `packageManager` + `.github/workflows/ci.yml`) — `bun.lockb` requires Bun 1.3.x.
- Web app: `apps/web` (Next.js 16.4.5/Turbopack). Extension: `apps/extension` (WXT). Shared client: `packages/latr-web-client`. The public LatrKit developer console and registration/key APIs are retired. Run `bash scripts/ci.sh` for Go and JS checks.
- Backend: `services/go-backend` — Go bookmark gateway (`go run ./cmd/gateway`, port 8080) and metadata service (`go run ./cmd/metadata`, port 8081). One Vercel Services project hosts frontend and both backends; Preview and Production use separate $0 Turso databases. See `docs/deployment/vercel-migration.md` and `services/go-backend/.env.example`.
- **LatrKit** remains the remote Swift client library used by native apps: https://github.com/CountableNewt/latr-kit. The hosted Swift server was removed; its old source is available in Git history at `009e734`.
- Web TS contracts + lexicons: **`latr-packages`** git dependency at repo root (`github:Stygian-Tech/latr-packages#<commit>`); import via `latr-packages/gateway-client`, `latr-packages/record-keys`, and `latr-packages/lexicons/*` with `transpilePackages: ["latr-packages"]` in `next.config.ts`. Do **not** duplicate lexicon JSON under `packages/lexicons/` — canonical source is **Stygian-Tech/latr-packages** only.

## Conventions

- ATProto OAuth scopes must match `apps/web/public/client-metadata.json` — users must re-auth after scope changes.
- Local dev: loopback OAuth activates on **localhost / 127.0.0.1** without requiring `NODE_ENV=development` (works with `next start` too). Optional `NEXT_PUBLIC_APP_ENV=local` in `apps/web/.env.local`. Timeouts: `NEXT_PUBLIC_OAUTH_CLIENT_LOAD_TIMEOUT_MS`, `NEXT_PUBLIC_AUTH_RESTORE_TIMEOUT_MS` — see `apps/web/.env.example`. Auth UI also forces loading off after 4s (`useAuth` failsafe). Use `http://127.0.0.1:3000` when testing OAuth.
- **Hosted:** Vercel production builds default to `prod`, previews to `dev`; other hosts must configure `NEXT_PUBLIC_APP_ENV`. Browser calls stay on `/api/latr-gateway/*`; service bindings supply `LATR_GATEWAY_INTERNAL_URL` and `LATR_METADATA_INTERNAL_URL`. Public pages/library shells are static; authenticated APIs are dynamic/no-store. Keep `syncLatrGatewayFromBrowser()` on mount and hydration-safe root markup.

## Learned User Preferences

- Canonical user-facing product title/branding: **L@tr.link** (metadata and primary headings), not abbreviated variants unless requested.
- When following an attached implementation plan in this repo: do not edit the plan artifact; reuse existing todos and update their status rather than creating duplicates.
- Favicon and Apple touch icons should be PNGs with transparency outside the blue squircle; OG/social artwork can remain full-bleed.
- Hosted backend code is **Go**. Next.js retains only the same-origin credential proxy and OAuth metadata. Native Swift client libraries stay Swift.
- **`LatrKit` is Swift-only** with Apple-style API naming (`SavedLibrary`, `RepositoryClient`, preposition-first methods); web record keys, gateway headers, and upstream DPoP proof pools come from **`latr-packages`** (`latr-packages/record-keys`, `latr-packages/gateway-client`), not duplicated in `apps/web`.
- Store bookmarks in `community.lexicon.bookmarks.bookmark` and durable reading state in `link.latr.bookmarks.metadata` on the user’s PDS. Derived previews and atomic DPoP replay claims live in Turso.
- Stygian openness model: three tiers — hosted SaaS, self-hosted reference services, and build-your-own public packages; hybrid repo split (focused foundation repos + grouped product-domain repos until APIs settle).
- Public foundation packages use descriptive names (`ATProtoPrimitiveKit`, `ATProtoAuthKit`, …), not a `Stygian` prefix; app-specific packages (`latr-kit`, `latr-packages`, …) keep product names.
- Shared package dependencies should resolve via git/npm/SwiftPM remotes — not sibling local paths — so CI and contributors run without monorepo-local checkouts.
- Go backend checks include race tests, vet, build, generated-contract parity and migration rehearsals. Preserve metadata golden fixtures and unknown PDS fields.
- Official gateway credentials should be server-side secrets. L@tr web uses the same-origin Next.js **`/api/latr-gateway/*`** proxy, which forwards OAuth/DPoP headers and injects **`LATR_GATEWAY_CLIENT_CREDENTIAL`** or split **`LATR_GATEWAY_CLIENT_ID`** + **`LATR_GATEWAY_API_KEY`** server-side; do **not** expose these as `NEXT_PUBLIC_*` or serialize them into the client. The extension uses **`VITE_*`** — interim for browser-direct gateway calls. Third-party clients use the registration API separately.

## Learned Workspace Facts

- **the-social-wire**: sibling Turborepo (`../the-social-wire`) — web read-later **mutations** (save/archive/delete) call **latr-gateway HTTP** via `readLaterProvider` (default); list may still read PDS directly. Official client id `the-social-wire-web` + base64 credential in env + viewer OAuth/DPoP; not a Swift `LatrKit` import in the web app.
- **Extraction repos**: 13 public GitHub repos under `Stygian-Tech` — foundation (`atproto-primitive-kit`, `atproto-auth-kit`, `gateway-trust-kit`, `federation-content-kit`, `mcp-server-kit`, `offline-sync-kit`), L@tr domain (`latr-kit`, `latr-packages`, `latr-reference`), Social Wire domain (`social-wire-appview-kit`, `social-wire-packages`, `social-wire-reference`), meta `reference-deploy`; guide at `reference-deploy/docs/repository-guide.md`. Provision via parent-dir `scripts/provision-github-repos.sh`.
- **Contract parity**: L@tr/read-state deterministic keys must match across Swift, TS, and iOS via golden vectors in **`latr-packages`** (`packages/record-keys/fixtures/stygian-golden-vectors.v1.json`, installed via the root git dependency) — key drift is a hard blocker.
- **Gateway client auth** is internal-only configuration: split `X-Latr-Client-Id`/`X-Latr-API-Key` or `X-Latr-Official-Client`, configured with `LATR_GATEWAY_OFFICIAL_CLIENT_CREDENTIALS`. Existing first-party hashes support rotations; there is no public registration, developer database or key issuance. The proxy signs the original method/URL using server-only `LATR_GATEWAY_PROXY_SECRET` so DPoP remains bound across Vercel service hops.
- **latr.link** is ATProto read-later with PDS-owned community bookmarks and L@tr metadata. Current operations are `link.latr.bookmarks.*`, `link.latr.preview.getOpenGraph`, `link.latr.discovery.resolveUrl` and `link.latr.auth.probe`. `/v1/latr/*`, `link.latr.saved.*` and `link.latr.developer.*` are retired.
- **GitHub Actions CI** verifies Go/Bun/native clients on main/dev pushes and PRs. Vercel Git integration deploys branch-scoped previews and main production in one project. CI never connects to hosted databases. Apply Turso schema/preview-cache transfer explicitly with `scripts/turso-migrate.py`.
- **Hosted testing** uses a Vercel branch preview in the same project as production. Only a selected preview domain receives a protection exception for public OAuth metadata; other deployment URLs stay protected. Historical `testing.latr.link`/`api.testing.latr.link` are compatibility domains, never separate Dev projects.
- **Upstream DPoP**: web clients precompute proofs via **`latr-packages/gateway-client`** (`createUpstreamDpopProof`, `createUpstreamDpopProofPool`, `createSaveUpstreamDpopProofPool`); gateway consumes them through **`UpstreamProofPool`** (one proof per PDS XRPC call).
- **Browser extension deploy**: no hosted publish pipeline (unlike web/gateway); test builds bake `VITE_*` env at build time and load unpacked — see `docs/apps/extension.md`.
- **Backend boundary**: Go services and shared internal packages live in `services/go-backend`. Web/native/extension clients call HTTP APIs. Do not reintroduce the retired Swift server, TS metadata fetch endpoints, public developer console, or legacy REST/save APIs.
